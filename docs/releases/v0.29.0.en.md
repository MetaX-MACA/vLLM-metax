# vLLM-MetaX v0.29.0 User Guide

> This is the per-release user guide shipped with vLLM-MetaX v0.29.0, for users and delivery teams deploying large models on MetaX GPU (MACA).
> Since v0.24.0, each release ships with a matching guide, kept together under `docs/releases/`.
>
> Repository: <https://github.com/MetaX-MACA/vLLM-metax>

vLLM-MetaX is a hardware backend plugin for vLLM, following vLLM's hardware-pluggable RFCs (#11162, #19161), and plugs into upstream vLLM as a plugin. This document is a **quick-start and release-notes** guide for the MetaX platform. For general vLLM usage, source builds, and precision debugging, follow the links in "Related Documentation" at the end.

## 1. Using vLLM-MetaX on the MetaX Platform

You can either build your own image or pull a prebuilt one. This guide uses a prebuilt image as the example.

### 1.1. Pull the image

```bash
docker pull cr.metax-tech.com/public-ai-release/maca/vllm-metax:0.29.0-maca.ai3.8.2.2-torch2.10-py312-ubuntu22.04-amd64
# tag convention (subject to the actual release page):
#   0.29.0            -> plugin version
#   maca.ai3.8.2.2    -> MACA driver version
#   torch2.10         -> torch version
#   py312-ubuntu22.04 -> base environment
```

### 1.2. Launch the container

```bash
# Metax GPU devices must be mounted via --device: --device=/dev/dri --device=/dev/mxcd
# The serving port must be exposed; --network=host is used here for convenience
docker run -it --net=host --uts=host --ipc=host --privileged=true --group-add video \
    --shm-size '100gb' --ulimit memlock=-1 \
    --security-opt seccomp=unconfined --security-opt apparmor=unconfined \
    --device=/dev/dri --device=/dev/mxcd \
    -v /root/workspace:/external \
    -v /model_weights:/model_weights \
    --name vllm_metax_test \
    cr.metax-tech.com/public-ai-release/maca/vllm-metax:0.29.0-maca.ai3.8.2.2-torch2.10-py312-ubuntu22.04-amd64
```

> See <https://developer.metax-tech.com> for more. For source builds, environment variables (MACA_PATH / CUCC_PATH, etc.) and build caveats, see the [MACA Installation Guide](../getting_started/installation/maca.md).

## 3. Run an Example

The image already contains matching versions of vLLM-MetaX and mcoplib, so you can start the OpenAI-compatible serving endpoint directly.

### 3.1. Start the vLLM serving endpoint

```bash
# example with Qwen3-8B; adjust the model path as needed
vllm serve /model_weights/Qwen/Qwen3-8B \
    --tensor-parallel-size 1 \
    --host 0.0.0.0 --port 8000
```

Key logs on a successful startup (excerpt):

```text
INFO 03-09 15:43:01 [api_server.py] Starting vLLM API server on http://0.0.0.0:8000
INFO 03-09 15:43:05 [core.py] Initializing a V1 LLM engine (v0.29.0) with config: ...
INFO 03-09 15:43:12 [maca_platform.py] MACA backend initialized, driver maca3.8.2.2
INFO 03-09 15:43:35 [gpu_model_runner.py] Model loading took 23.41 GiB and 22.65 seconds
INFO 03-09 15:43:36 [api_server.py] Application startup complete.
```

### 3.2. Send an inference request

```bash
curl http://localhost:8000/v1/completions \
    -H "Content-Type: application/json" \
    -d '{
        "model": "/model_weights/Qwen/Qwen3-8B",
        "prompt": "MetaX is a",
        "max_tokens": 32
    }'
```

Example response:

```json
{
  "id": "cmpl-xxxxxxxx",
  "object": "text_completion",
  "model": "/model_weights/Qwen/Qwen3-8B",
  "choices": [
    { "text": " company focused on high-performance AI computing, whose MACA software stack is CUDA-compatible.", "index": 0, "finish_reason": "length" }
  ],
  "usage": { "prompt_tokens": 4, "completion_tokens": 32, "total_tokens": 36 }
}
```

> For more launch options, parallelism strategies (tensor/pipeline/expert parallel), and quantized weight loading, see the [vLLM documentation](https://docs.vllm.ai/). Section 3.1 only demonstrates a minimal runnable example.

### 3.3. Other versions / build from source

To build another version or customize, use MACA-compatible packages. The build depends on torch 2.10 (metax3.8.2.2); use `--no-deps` to avoid overwriting an existing PyTorch in the environment:

```bash
# the 0.29.0 development line is currently `master`; update this if a mx/v0.29.0-dev branch is created
git clone -b master https://github.com/MetaX-MACA/vLLM-metax.git
cd vLLM-metax
pip install -r requirements/maca.txt -r requirements/maca_private.txt
pip install -e . --no-deps
```

After any environment change, verify the PyTorch version and availability:

```bash
pip list | grep torch
# torch                    2.10.0+metax3.8.2.2
```

```python
import torch
torch.cuda.is_available()  # True
```

> Full build flow (building vllm itself with the empty device, the meaning of USE_PRECOMPILED_KERNEL, and the requirement to use mcoplib in production) is in the [MACA Installation Guide](../getting_started/installation/maca.md).

## 4. v0.29.0 Highlights

- **Aligned with upstream vLLM v0.29.0**
    - Plugin version bumped to 0.29.0 and the dependency matrix re-aligned for v0.29.0 (transformers >= 5.10.4, huggingface_hub >= 1.28.0)
- **DeepSeek-V4**
    - Fixed the topk global-index block-table out-of-bounds: the kernel now bounds-checks the block-table rows/columns, clamps the pointer operands, and packs surviving entries to the front of each row; out-of-bounds gathers on CUDA-graph padding or mixed decode+prefill batches faulted at the hardware level (Xnack/ATU trap on MACA)
- **MoE / quantization**
    - Dropped the import of `compressed_tensors_moe_wna16_marlin` (removed upstream)
    - Removed the `MACA_VLLM_ENABLE_MCTLASS_PYTHON_API` switch; MCTLASS uses a single implementation
    - auto_awq layer skipping now uses `match_mode="substring"` (upstream dropped `skip_with_substr`)
- **MiniMax-M3**
    - `_MINIMAX_FUSED_AR_RMS_QK` (qk_norm all-reduce fusion) disabled by default
    - index_topk patches stacked on every import site; the load_weights patch retargeted to `MiniMaxM3Model.load_weights`
- **Qwen3-VL-MoE**
    - Per-channel scale normalisation for transposed fused checkpoints (upstream PR #50137 only covers the fused weights)
- **Speculative decoding / MLA**
    - MC3-14634: MLAPO reverted to the previous implementation to avoid draft token index reuse
- **Toolchain / dependencies**
    - metax3.8.2.2 toolchain; mcoplib relaxed to `>=0.4.11` (no longer a fixed hash; subject to the release image)
    - Added tilelang 0.1.12+maca, apache-tvm-ffi 0.1.11+maca and maca-python 0.0.1; nixl / mooncake-transfer-engine updated
    - numba 0.65.0; xgrammar 0.2.x
- **Tools / engineering**
    - msprobe dumps install `MacaWorker` and now log the override
    - batched_test tools refactored for quick verification
- **Ported from previous releases and kept on this branch**
    - MiniMax-M3-FP8 / Qwen3.5 MTP / telechat3-yarn / bytes_to_unicode / MLA chunked-prefill int8 / SparseAttnIndexer (0.29 carries the adapted versions)

## 5. New and Updated Models

These models are new or significantly updated in v0.29.0 (some are not yet reflected in `docs/models/supported_models.md` — this guide is authoritative):

### Text / reasoning models

- **DeepSeek-V4**: topk global-index block-table out-of-bounds guard (new `bugfix/deepseek_v4/topk_global_indices_oob.py`), bf16 FlashMLA padding-heads fix, DSpark main_proj BF16
- **MiniMax-M3**: `_MINIMAX_FUSED_AR_RMS_QK` disabled by default; index_topk / load_weights patches corrected
- **Qwen3.5 series**: MTP weight-loading patch (int8 shared-expert gate dequantization) carried to 0.29
- **JD JoyAI**: `JoyAI_LLM_Flash` (jd) support kept through the model sync
- **DeepSeek series / GLM and others**: follow the v0.29.0 upstream baseline and model sync

### Multimodal models

- Models supported by the upstream v0.29.0 baseline (Qwen3-Omni / Qwen3-VL, Intern series, etc.) remain available; this release adds weight-loading support for transposed fused Qwen3-VL-MoE (W8A8 / int8) checkpoints

### Quantized model support

- FP8 / int8_w8a8 / W8A8; MiniMax-M3-FP8 weight-loading patch carried to 0.29; auto_awq matching mode and the compressed_tensors wna16 import adapted to upstream v0.29; `w8a8_int8` restricted to the EP (deep_ep) path

> The full list of tested models and feature status (LoRA, PP, etc.) is in [Supported Models](../models/supported_models.md).
> To onboard a model not in the list or a customized model, see the [Model Registration Guide](../developing/model/registration.md).

## 6. Upgrading from v0.28

1. **Switch image / environment**: docker users switch directly to the v0.29.0 image; source users re-checkout `master` (the 0.29.0 development line) and reinstall deps as in 3.3.
2. **torch / MACA**: v0.29.0 uses the same torch 2.10 (metax3.8.2.2) as v0.28.0; if the release page announces a new MACA version, follow it and rebuild locally built csrc against the current `requirements/`.
3. **mcoplib**: requirements relax the pin to `>=0.4.11` (v0.28.0 pinned `0.4.11+g0cb4f49.maca3.8.2.6.torch2.10`); use the prebuilt mcoplib that matches the release image, otherwise kernel symbols will not match.
4. **Dependency changes**: transformers >= 5.10.4, huggingface_hub >= 1.28.0; new tilelang, apache-tvm-ffi and maca-python dependencies; nixl / mooncake-transfer-engine updated — install strictly per `requirements/`.
5. **MCTLASS environment variable**: `MACA_VLLM_ENABLE_MCTLASS_PYTHON_API` was removed, so setting it in existing launch scripts has no effect; clean it up.
6. **Patch changes**: new DeepSeek-V4 topk out-of-bounds guard (`bugfix/deepseek_v4/topk_global_indices_oob.py`). The RoutedExperts fused weight orientation fix (PR #50137) only covers the fused weights, so per-channel scales of transposed fused checkpoints (Qwen3-VL-MoE) still need `bugfix/routed_experts_fused_weight_fix.py` (without it, loading Qwen3-VL-235B-A22B-Instruct_W8A8 fails with `output with shape [1, 1] doesn't match the broadcast shape [1, 4096]`). MiniMax-M3 topk buffer layout (#49149) is fixed upstream in v0.27+, so that monkeypatch is no longer needed.
7. **Quantization paths**: auto_awq uses `match_mode="substring"`; compressed_tensors wna16 no longer imports `compressed_tensors_moe_wna16_marlin`.
8. **Speculative decoding**: MLAPO reverted to the previous implementation to avoid draft token index reuse (MC3-14634); regression-test eagle / MTP proposal accuracy after upgrade.

## 7. Differences from NVIDIA CUDA

MetaX aligns with NVIDIA on most interfaces, but differs in some software behaviors and environment variables.

### 7.1. MACA_MPS_MODE (multi-process GPU sharing)

By default, MACA does not allow multiple processes to share one GPU. If a GPU is occupied, a new process cannot start.

To enable an MPS-like (Multi-Process Service) feature, set: `MACA_MPS_MODE=1`

```bash
export MACA_MPS_MODE=1
vllm serve /model_weights/Qwen/Qwen3-8B --tensor-parallel-size 1
```

### 7.2. Multi-node deployment

When vLLM runs distributed (tensor/pipeline/expert parallel) across nodes, set the following environment variables to keep inter-node communication healthy:

- `MCCL_SOCKET_IFNAME`: network interface for MCCL
- `GLOO_SOCKET_IFNAME`: network interface for GLOO
- `MCCL_IB_HCA`: the InfiniBand devices to use

Determine the NIC and IB devices via `ifconfig` and `mx-smi topo -n` (see the topology examples in the verl / Megatron docs). Recommended settings:

```bash
export MCCL_SOCKET_IFNAME=ens20f0np0
export GLOO_SOCKET_IFNAME=ens20f0np0
export MCCL_IB_HCA=mlx5_0,mlx5_1,mlx5_2,mlx5_3
```

> ⚠️ Adjust according to your own machine's `ifconfig` and `mx-smi topo -n` output; do not blindly copy the commands above.

## 8. Known Issues and Workarounds

| Issue | Impact | Workaround / status |
| --- | --- | --- |
| `compressed_tensors_moe_wna16_marlin` removed upstream (since v0.28.0) | Old imports fail | Import removed on this branch |
| `MACA_VLLM_ENABLE_MCTLASS_PYTHON_API` removed | The variable has no effect, MCTLASS uses a single implementation | Clean up old launch scripts; regression-test if you relied on the old behavior |
| DeepSeek-V4 topk global-index out-of-bounds (upstream #55636; candidates #55692 / #55744 not merged) | Out-of-bounds block-table gathers on CUDA-graph padding / mixed decode+prefill batches can fault at the hardware level (Xnack/ATU on MACA) | Patched on this branch by `bugfix/deepseek_v4/topk_global_indices_oob.py`; regression-test with DeepSeek-V4-Flash W8A8 at batch 32 before release |
| MiniMax-M3 topk buffer layout (#49149) | Affects v0.26 and earlier | Fixed upstream in v0.27+; no patch needed |
| Per-channel scales of transposed fused checkpoints (PR #50137 follow-up) | Qwen3-VL-MoE W8A8 and similar models fail to load | Upstream only handles the fused weights; `bugfix/routed_experts_fused_weight_fix.py` is still required |
| `minimax_qk_norm` all-reduce fusion disabled by default (`_MINIMAX_FUSED_AR_RMS_QK`) | Fusion ops off by default, slightly lower perf on affected models and extra workspace needed when enabled | To enable, change the `rms_norm_tp` config and regression-test accuracy |
| msprobe precision dumps require `--enforce-eager` | Without the flag, startup raises (CUDA graph capture bypasses the Python-level hooks) | Add `--enforce-eager` as the error message asks, then capture |
| MiniMax-M3-FP8 / Qwen3.5 MTP / telechat3-yarn patches | Runtime behavior needs validation | Smoke-test the corresponding model loads before release |
| deep_ep / mctlass / W4A8 and other quantization paths | Regression-test accuracy | On accuracy deviation, capture and compare with msprobe ([guide](../developing/msprobe/msprobe_guide.md)) |
| Some tokenizers under transformers v5 (Moonlight / Kimi, etc.) | Old import path (`bytes_to_unicode`) removed in transformers v5 | 0.29 carries a compatibility implementation; pin the transformers version if issues persist |
| Locally built csrc vs prebuilt mcoplib | Local builds must match the image's mcoplib (>=0.4.11) kernel symbols | Prefer the prebuilt mcoplib combination in production |
| tilelang / tvm-ffi / xgrammar / maca-python tightly coupled | Mixing combinations may break kernel loading or grammar | Install strictly per `requirements/` |
| v0.16.0 officially skipped | No such version | Do not use v0.16.x |
