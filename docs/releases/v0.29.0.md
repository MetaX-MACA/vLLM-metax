# vLLM-MetaX v0.29.0 使用指导手册

> 本文是 vLLM-MetaX v0.29.0 版本随版发布的用户指导手册，面向在 MetaX GPU（MACA）上部署大模型的用户与交付团队。
> 从 v0.24.0 起，每个发布版本都会附一份对应的指导手册，统一记录在 `docs/releases/` 下。
>
> 仓库地址：<https://github.com/MetaX-MACA/vLLM-metax>

vLLM-MetaX 是 vLLM 的硬件后端插件（plugin），遵循 vLLM 的硬件可插拔 RFC（#11162、#19161），以插件形式接入上游 vLLM。本文是 MetaX 平台上的**快速上手与版本说明**，通用 vLLM 用法、从源码构建、精度调测等深入内容请参考文末「相关文档」中的对应链接。

## 1. 在 Metax 平台上使用 vLLM-MetaX

你可以选择构建自己的镜像，也可以直接拉取已有的预构建镜像。本文以拉取预构建镜像为例。

### 1.1. 拉取镜像

```bash
docker pull cr.metax-tech.com/public-ai-release/maca/vllm-metax:0.29.0-maca.ai3.8.2.2-torch2.10-py312-ubuntu22.04-amd64
# 示例 tag 规则（以实际发布页为准）：
#   0.29.0            -> 插件版本
#   maca.ai3.8.2.2    -> MACA 驱动版本
#   torch2.10         -> torch 版本
#   py312-ubuntu22.04 -> 基础环境
```

### 1.2. 启动容器

```bash
# 必须通过 --device 挂载 Metax GPU 设备：--device=/dev/dri --device=/dev/mxcd
# 推理服务需要暴露端口，这里用 --network=host 方便直接访问
docker run -it --net=host --uts=host --ipc=host --privileged=true --group-add video \
    --shm-size '100gb' --ulimit memlock=-1 \
    --security-opt seccomp=unconfined --security-opt apparmor=unconfined \
    --device=/dev/dri --device=/dev/mxcd \
    -v /root/workspace:/external \
    -v /model_weights:/model_weights \
    --name vllm_metax_test \
    cr.metax-tech.com/public-ai-release/maca/vllm-metax:0.29.0-maca.ai3.8.2.2-torch2.10-py312-ubuntu22.04-amd64
```

> 更多信息请参考官方文档：<https://developer.metax-tech.com>
> 从源码构建、环境变量（MACA_PATH / CUCC_PATH 等）与构建注意事项，详见 [MACA 安装指南](../getting_started/installation/maca.md)。

## 3. 运行示例

镜像内已包含匹配版本的 vLLM-MetaX 与 mcoplib，可直接启动 OpenAI 兼容推理服务。

### 3.1. 启动 vLLM 推理服务

```bash
# 以 Qwen3-8B 为例，请根据实际模型路径修改
vllm serve /model_weights/Qwen/Qwen3-8B \
    --tensor-parallel-size 1 \
    --host 0.0.0.0 --port 8000
```

服务启动成功的关键日志（节选）：

```text

INFO 03-09 15:43:35 [gpu_model_runner.py] Model loading took 23.41 GiB and 22.65 seconds
```

```bash
curl http://localhost:8000/v1/completions \
    -H "Content-Type: application/json" \
```

### 3.3. 使用其他版本 / 从源码构建

如需构建其他版本或定制，需使用与 MACA 兼容的软件包。编译依赖 torch 2.10（metax3.8.2.2），建议使用 `--no-deps` 避免覆盖环境内已有 PyTorch：

```bash

pip install -e . --no-deps
```

环境变更后请检查 PyTorch 版本及其可用性：

```bash
pip list | grep torch
# torch                    2.10.0+metax3.8.2.2
```

```python

```

## 4. v0.29.0 本版本重点新特性

- **同步上游 vLLM v0.29.0**
    - 插件版本号提升至 0.29.0，依赖矩阵按 v0.29.0 重新对齐（transformers >= 5.10.4、huggingface_hub >= 1.28.0）
- **DeepSeek-V4**
    - 修复 topk global index 的 block table 越界：kernel 增加 block table 行/列边界判断、钳制指针操作数，并把有效项打包到行首；CUDA-graph padding 或混合 decode+prefill 批次下越界访存会触发硬件级异常（MACA 侧 Xnack/ATU 陷阱）
- **MoE / 量化**
    - 移除上游已删除的 `compressed_tensors_moe_wna16_marlin` 导入
    - `MACA_VLLM_ENABLE_MCTLASS_PYTHON_API` 开关移除，MCTLASS 走固定实现
    - auto_awq 的层跳过改用 `match_mode="substring"`（上游已移除 `skip_with_substr`）
- **MiniMax-M3**
    - `_MINIMAX_FUSED_AR_RMS_QK`（qk_norm all-reduce 融合）默认关闭
    - index_topk 补丁叠加到全部导入点；load_weights 补丁改指向 `MiniMaxM3Model.load_weights`
- **Qwen3-VL-MoE**
    - 转置 fused checkpoint 的 per-channel scale 归一化（上游 PR #50137 只覆盖融合权重）
- **投机解码 / MLA**
    - MC3-14634：MLAPO 回退到旧实现，避免 draft token index 复用
- **工具链 / 依赖**
    - metax3.8.2.2 工具链；mcoplib 放宽为 `>=0.4.11`（不再固定 hash，以发布镜像为准）
    - 新增 tilelang 0.1.12+maca、apache-tvm-ffi 0.1.11+maca、maca-python 0.0.1；nixl / mooncake-transfer-engine 版本更新
    - numba 0.65.0；xgrammar 0.2.x
- **工具 / 工程**
    - msprobe dump 安装 `MacaWorker` 并打印提示日志
    - batched_test 工具重构，便于快速验证
- **随前序版本移植并保留在本分支**
    - MiniMax-M3-FP8 / Qwen3.5 MTP / telechat3-yarn / bytes_to_unicode / MLA chunked-prefill int8 / SparseAttnIndexer 等（0.29 已有等价适配版本）

## 6. 从 v0.28 升级迁移

1. **更换镜像 / 环境**：docker 用户直接切到 v0.29.0 镜像；源码用户重新 checkout `master`（0.29.0 开发线）并按 3.3 重装依赖。
2. **torch / MACA**：v0.29.0 与 v0.28.0 同为 torch 2.10（metax3.8.2.2）；若发布页给出新的 MACA 版本，以发布页为准，本地编译的 csrc 需按当前 `requirements/` 重新编译。
3. **mcoplib**：requirements 中已放宽为 `>=0.4.11`（v0.28.0 固定为 `0.4.11+g0cb4f49.maca3.8.2.6.torch2.10`）；生产环境请使用与发布镜像一致的预编译 mcoplib，避免内核符号不匹配。
4. **依赖变化**：transformers >= 5.10.4、huggingface_hub >= 1.28.0；新增 tilelang、apache-tvm-ffi、maca-python 依赖；nixl / mooncake-transfer-engine 版本更新，严格按 `requirements/` 安装。
5. **MCTLASS 环境变量**：`MACA_VLLM_ENABLE_MCTLASS_PYTHON_API` 已移除，旧启动脚本中的设置不再生效，需清理。
6. **补丁变化**：新增 DeepSeek-V4 topk 越界防护补丁 `bugfix/deepseek_v4/topk_global_indices_oob.py`；RoutedExperts 的 fused weight 方向（PR #50137）上游只覆盖融合权重，Qwen3-VL-MoE 这类转置 fused checkpoint 的 per-channel scale 仍需本分支补丁 `bugfix/routed_experts_fused_weight_fix.py`（未打补丁时加载 Qwen3-VL-235B-A22B-Instruct_W8A8 会报 `output with shape [1, 1] doesn't match the broadcast shape [1, 4096]`）；MiniMax-M3 topk buffer 布局（#49149）在 v0.27+ 上游已含，相关 monkeypatch 无需再打。
7. **量化路径**：auto_awq 使用 `match_mode="substring"`；compressed_tensors wna16 已移除对 `compressed_tensors_moe_wna16_marlin` 的导入。
8. **投机解码**：MLAPO 回退到旧实现以避免 draft token index 复用（MC3-14634）；升级后回归测试 eagle / MTP 提议精度。

## 7. Metax 与 NVIDIA CUDA 的差异

Metax 在大部分接口上与 NVIDIA 对齐，但在某些软件行为和环境变量上存在差异。

### 7.1. MACA_MPS_MODE（多进程共享 GPU）

默认情况下，MACA 不允许多个进程共享同一块 GPU。如果 GPU 已被占用，则无法启动新进程。

如需启用类似 MPS（Multi-Process Service）的功能，需设置：`MACA_MPS_MODE=1`

```bash
export MACA_MPS_MODE=1
vllm serve /model_weights/Qwen/Qwen3-8B --tensor-parallel-size 1
```

### 7.2. 多节点部署

vLLM 分布式（tensor/pipeline/expert parallel）跨节点时，建议设置以下环境变量以确保节点间通信正常：

- `MCCL_SOCKET_IFNAME`：用于 MCCL 通信的网络接口
- `GLOO_SOCKET_IFNAME`：用于 GLOO 通信的网络接口
- `MCCL_IB_HCA`：指定使用的 InfiniBand 设备

可通过 `ifconfig` 和 `mx-smi topo -n` 确定所用网卡和 IB 设备（参考 verl / Megatron 文档中的拓扑示例）。推荐设置：

```bash
export MCCL_SOCKET_IFNAME=ens20f0np0
export GLOO_SOCKET_IFNAME=ens20f0np0
export MCCL_IB_HCA=mlx5_0,mlx5_1,mlx5_2,mlx5_3
```

> ⚠️ 请根据自己机器的 `ifconfig` 和 `mx-smi topo -n` 输出进行相应调整，切勿盲目复制上述命令。

## 8. 已知问题与规避

| 问题 | 影响 | 规避 / 状态 |
| --- | --- | --- |
| `compressed_tensors_moe_wna16_marlin` 在上游已移除（v0.28.0 起） | 旧代码 import 会失败 | 已移除该导入（本分支已修复） |
| `MACA_VLLM_ENABLE_MCTLASS_PYTHON_API` 已移除 | 旧脚本中的环境变量失效，MCTLASS 走固定实现 | 清理旧启动脚本；依赖旧行为时回归验证 |
| DeepSeek-V4 topk global index 越界（上游 #55636，候选 #55692 / #55744 未合入） | CUDA-graph padding / 混合 decode+prefill 批次下 block table 越界访存，可能触发硬件级异常（MACA 侧 Xnack/ATU） | 本分支补丁 `bugfix/deepseek_v4/topk_global_indices_oob.py`；发布前用 DeepSeek-V4-Flash W8A8 batch 32 回归 |
| MiniMax-M3 topk buffer 布局（#49149） | v0.26 及更早受影响 | 上游 v0.27+ 已修复，无需补丁 |
| RoutedExperts 转置 fused checkpoint 的 per-channel scale（PR #50137 follow-up） | Qwen3-VL-MoE W8A8 等转置 fused 模型加载失败 | 上游仅处理融合权重，仍需 `bugfix/routed_experts_fused_weight_fix.py` |
| `minimax_qk_norm` all-reduce fusion 默认关闭（`_MINIMAX_FUSED_AR_RMS_QK`） | 该融合算子默认不启用，相关模型性能略低，且需要额外 workspace | 如需开启请修改 `rms_norm_tp` 相关配置并回归精度 |
| msprobe 精度 dump 必须配合 `--enforce-eager` | 未加该参数时直接报错（CUDA graph 会绕过 Python 钩子） | 按提示加上 `--enforce-eager` 后再抓取对比 |
| MiniMax-M3-FP8 / Qwen3.5 MTP / telechat3-yarn 等补丁 | 运行时行为需实测 | 发布前加载对应模型验证 |
| deep_ep / mctlass / W4A8 等量化路径 | 需回归验证精度 | 精度异常时用 msprobe 抓取对比（[指南](../developing/msprobe/msprobe_guide.md)） |
| transformers v5 下部分 tokenizer（Moonlight / Kimi 等） | 旧 import 路径（`bytes_to_unicode`）被移除 | 0.29 已有兼容实现；仍异常时锁定 transformers 版本 |
| 本地编译 csrc 与预编译 mcoplib 差异 | 本地编译需与镜像内 mcoplib（>=0.4.11）的内核符号匹配 | 生产环境建议使用预编译 mcoplib 组合 |
| tilelang / tvm-ffi / xgrammar / maca-python 强匹配 | 混用组合可能导致内核加载或 grammar 异常 | 严格按 `requirements/` 中的组合安装 |
| v0.16.0 被官方跳过 | 无此版本 | 请勿使用 v0.16.x |
